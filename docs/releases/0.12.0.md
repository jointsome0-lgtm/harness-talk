# htalk 0.12.0

This version adds an explicitly configured SSH route to the profile catalogue. A known client can fetch the current directory and select a profile without mDNS, an active Bluetooth PAN or a Tailscale daemon. The destination must already be reachable. This change does not provide NAT traversal, cellular setup or automatic failover.

## Try the route

Upgrade every client reading a shared trust file before adding the optional `ssh_address` field to its private trusted-device entry. Use a literal unicast IPv4 address and retain the device/mailbox/generation/sender, SSH user/port/key and verified host-key pins. Older clients reject the new field. Existing trust files remain valid for the new client. Trust schema remains 1.

```sh
htalk catalog discover --trust /absolute/private/htalk/trust.json --via ssh
htalk catalog connect 'Reviewer' --trust /absolute/private/htalk/trust.json --via ssh
```

The client fetches only configured trusted devices. It checks the existing SSH and deployment/profile bindings before mailbox operations. An open client retains its selected address and profile binding. Change the private trust entry and explicitly reconnect to choose a new address. Keep unknown outcomes and their original request IDs; the route does not retry a lost mailbox response or send another notification automatically. See [catalogue configuration and selection](../catalog.md).

## Upgrade and recovery

Mailbox schema remains 3. Existing schema-3 mailboxes need no migration. The first ordinary command opening a supported schema-1/2 mailbox still creates and verifies a private SQLite backup in `MAILBOX_PATH.backups`, then migrates it to schema 3 in one transaction. Htalk never restores an old backup automatically. Preserve databases, catalogue/trust files, native state and receipts; catalogue configuration is separate from a SQLite backup.

Stop writers and receivers before replacing their CLI and matching adapter files. Preserve a consistent mailbox backup using SQLite's backup API and copy the private configuration and receiver state while their writers are stopped. Update every installation sharing the mailbox, and obtain matching adapter files from the 0.12.0 source archive. For a uv-installed CLI with a matching published Linux wheel:

```sh
uv tool install --force --no-build harness-talk==0.12.0
htalk --version
htalk peer list
```

Without uv, run `python -m pip install --upgrade harness-talk==0.12.0` in the intended environment. The remote catalogue endpoint retains its restricted forced command, fixed database and sender. Verify the selected profile, a read-only mailbox call, passive receiver status and existing receipts before resuming work. Do not reset state or resend an uncertain message to recover. The [0.11.0 adapter, recovery and Linux/pidfd requirements](0.11.0.md#upgrade) still apply.

Rollback requires stopping affected processes and preserving their current state. Remove `ssh_address` from trust files before using an older client and restore the previous explicit catalogue route, with matched CLI and adapter versions. Schema 3 remains compatible with 0.11.1, but the new direct catalogue route is unavailable there. Reverting the executable does not reverse native actions or reconcile uncertain work. Never restore an old mailbox over later messages.

## Source validation and limits

Eight Rust catalogue tests and 35 focused Python catalogue tests passed, including eight new direct-SSH tests with a temporary real loopback SSH server. They cover malformed and unavailable addresses, partial discovery, unique/ambiguous profile selection, host-key and deployment mismatch, changed/retired bindings, an open client's fixed endpoint, and a lost write response followed by explicit recovery using the original ID. Offline locked build, Clippy and formatting checks passed.

These source checks do not establish WAN or cellular native-agent exchange, present device availability or notification delivery through the new route. Historical Bluetooth/Tailscale dialogue checks relied on an existing LAN receiver. The seven open performance failures and earlier uncertain trials remain unresolved; this change does not repeat those trials or make a new performance claim.

The [dated native check](../checks/2026-10-05-0.12.0-native.md) records all 14 mandatory client exchanges, exact publish-run artifacts and public release verification. Codex and Claude checked both initiating directions with their selected models; twelve other clients used deterministic local providers. Cline's failed aggregate and original listener failure, Hermes/Gemini false aggregates, unobserved native exits and literal notification-cleanup limits remain recorded separately from exchange acceptance.
