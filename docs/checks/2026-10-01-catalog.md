## Native clients

Codex CLI 0.159.3 and Claude Code 2.1.285 completed one request and reply in
each initiating direction with GPT-6 Luna. Each message was read with `show`
before a separate `ack`; replies referred to their original requests.
Both final inboxes were empty and no send or reply was repeated.
Codex used ordinary automatic approval review; Claude used manual Bash
permissions and safe mode. The experiment does not establish official support
for using non-Claude models with Claude Code. Its bare-mode preflight failed
before creating messages because session socket metadata was absent.
Notification cleanup was absent or unsupported, so removal is not established.

OpenCode 1.18.32 completed MCP `show`, separate `ack` and a correlated `reply`
with a local canned provider. This checks delivery and native tool execution;
it does not check external inference. Other adapters were not rerun and retain
their earlier dated results. Owned test processes were closed after the checks.

## Catalogue connections

The source candidate completed a real request, reply and ACK through each
catalogue route: LAN/Wi-Fi mDNS, private Tailscale, and an active Bluetooth PAN.
Read-only connections recovered on all three routes after restarting catalogue
services. The published executable then passed read-only connections on both
devices with the saved mailbox, receiver ledger, profiles and bindings preserved.
Schema remains 3; upgrading from 0.9.6 required no migration.

Wake-up and replies used an existing LAN receiver during the live exchanges.
Independent notification delivery with other routes disabled remains untested.
An immediate discovery miss after restart had an unknown cause; subsequent
read-only checks passed. Channel selection is explicit; network activation,
automatic failover and agent startup are outside the catalogue's scope.
