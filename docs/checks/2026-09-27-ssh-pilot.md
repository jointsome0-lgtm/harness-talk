# Linux SSH mailbox pilot, 2026-09-27

Two owner-controlled Linux x86-64 devices completed a live exchange using
htalk 0.8.1, schema 3 and OpenSSH stdio transport. The worker ran Codex CLI
0.157.1 configured for GPT-6 Luna with medium effort through its existing
ChatGPT login. No OpenRouter key or account credentials were copied.

The one authoritative test mailbox was on the worker laptop. The PC connected
with a dedicated key bound to a fixed `htalk mcp` command, peer and database;
the worker used local MCP. Both participants were pull peers. There was no
production mailbox access or SQLite replication.

## Observed results

- The worker read and ACKed the PC's request, processed 50,000 synthetic CSV
  records into 17 group aggregates, and replied to the original ID.
- The PC independently computed the aggregates and downloaded the result
  artifact. All values and the complete file bytes matched.
- The worker sent a separate verification request; the PC replied, and the
  worker read and ACKed that response. The two requests and two replies had
  four correlated ACKs. The native run finished successfully.
- A requested shell command was replaced by the key's fixed MCP command.
  Identity/database overrides, registration, file input, a send without an ID,
  an oversized body and an unknown recipient were rejected.
- Reading, acknowledging, answering or waiting on another pair's synthetic
  message was rejected. Sending a new request to a retired peer was rejected.
- For a separate transport-only request, the controller observed the database
  commit while the caller was still waiting, then killed that SSH connection
  before it received the result. Reconnection found the original message.
  Replaying its ID and body returned `created: false`; a conflicting body was
  rejected. Exactly one request row remained.
- The native agent was launched once and executed one computation. Its
  execution record and exclusive start marker were unchanged by the transport
  experiment. No model was relaunched to recover the lost receipt.
- At completion both participant inboxes were empty, all control messages
  were closed, and no fixture processes remained. The temporary key was
  revoked and refused a fresh connection; the owner's original SSH access
  still worked. The temporary private key was deleted.

The computation had a 60-second CPU limit and a 512 MiB address-space limit.
The input and output were synthetic; private host addresses, keys, mailbox IDs
and full native logs remain in the owner's private receipts.

## Limits

This proves a pull exchange and bounded tool execution across one LAN. It
does not prove idle wakeups, offline queues on independent devices, arbitrary
task exactly-once execution, Bluetooth, WAN, native macOS or Windows support.
The model inference was cloud-hosted; the data-processing command ran on the
laptop. Losing the laptop also loses access to this pilot's mailbox.

The existing executable supplied the entire mailbox interface. No Rust changes,
new runtime dependencies or permanent automated tests were required for the
pilot. See the [SSH setup and recovery guide](../../integrations/ssh.md).
