# htalk 0.16.0 native check, October 23, 2026

Three installed clients completed the native exchange on Linux against the exact x86-64 wheel and source archive from [publish run 39947185061](https://github.com/jointsome0-lgtm/harness-talk/actions/runs/39947185061), source commit `ee8d95d2d1355f6186b1bc7f226c4f29cf25bbc0`: Codex and Claude Code as real sessions in both initiating directions, and OpenCode as a real server with a deterministic local provider. This is the scope the repository owner set for 0.13.0, kept since. The other eleven installed clients were not checked live for this release; their last live check is the [0.12.0 native check](2026-10-05-0.12.0-native.md).

No client ran on macOS or Windows. What is new in 0.16.0 is on Windows: a notice into Codex through its installed command. This check does not touch it. What stands behind it is the publish run on GitHub's hosted runners, against a fake client installed as npm installs the real one, described below. No real Codex has run on Windows, and no notice has reached a real session there; [#147](https://github.com/jointsome0-lgtm/harness-talk/issues/147) is that check. [What works on which system](../platforms.md) says what backs each part.

Each client ran as an ordinary interactive session in its own empty workspace, with the account's normal client configuration, in a terminal multiplexer started with a clean environment. The mailbox was new and the text invented. These were actual model calls. Token counts and billing were not measured, and the model names are the ones the clients displayed. No update was offered during the check. Claude Code showed its banner for an update it had installed before the check; it printed `2.1.309` before the check and after it.

Each recipient compared the shown id with the id in its notice and checked sender, recipient, body and `in_reply_to` before the ack. All four rows are acknowledged and both final inboxes are empty. Ack cleanup was literally `unsupported` with `client_has_no_notification_removal` for Claude and `absent` with the queue id for Codex. Neither proves that a notice was removed. Both clients ended with exit status 0 after their own quit command.

## OpenCode

OpenCode 1.18.32 ran as `opencode serve` on a loopback port with new state directories and a fake key. The model was a local script that speaks the chat-completions protocol on loopback, so no model call was made and the result says nothing about model comprehension. Only the htalk MCP tool, bound to the wheel's executable, was offered to it.

`peer check` reported the session as `idle` on a server of version 1.18.32. A pull peer acting as controller sent one question. htalk answered `submitted` with `opencode_prompt_async_accepted` and returned the answer inside its 45-second wait. The session's own history holds the notice once and three tool calls: show, ack, reply. The local provider checked id, sender, recipient, body and `in_reply_to` of the shown message before it asked for the ack. The controller showed the answer, checked that it answers the question, and acknowledged it separately. Both final inboxes are empty. The provider served five requests, one for the session title and four for the exchange.

Ack cleanup was literally `unsupported` with `client_has_no_notification_removal` in the session and `skipped` with `pull_only` at the controller; neither proves that a notice was removed. The server ended with -15 after SIGTERM, which is not a normal exit of its own. A request for port 0 selected 4096, so an OS-assigned port was not shown. No attached TUI was checked.

## Scope and limits

- Linux x86-64 only. No Codex, Claude Code or OpenCode ran on macOS or Windows, and no wheel but the Linux x86-64 one was executed outside the publish run.
- The route into Codex on Windows, which is what this release adds, was not exercised by any real client. A notice to a real Codex session on Windows is still to be seen, and so is any notice to a real session on a Mac.
- Not checked live for 0.16.0: Pi, Oh My Pi, OpenClaw, Cline, Kilo, Goose, Hermes, GitHub Copilot CLI, Gemini CLI, Letta Code and OpenHands. Here their adapters are covered only by the adapter tests of the publish run. Antigravity SDK and Agent Zero remain unchecked, as before.
- The notice names `htalk`. Both core sessions ran the wheel's absolute path in its place, because an older htalk is installed on the same machine. A notice followed word for word on a machine whose first `htalk` is 0.16.0 was not observed.
- One exchange in each direction. No interruption, recovery, concurrent writer or route between devices was exercised.
- Native exit was observed as an exit status. What htalk owns while it delivers, process groups, pidfds and listeners, was not observed closing in this check; the tests of the publish run cover it.
- The clients used the account's normal configuration and network. Nothing is claimed about the processes or the traffic of the whole host.
- The installed clients and the older installed htalk were not changed by this check.
