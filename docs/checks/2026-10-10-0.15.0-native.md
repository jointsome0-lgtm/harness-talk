# htalk 0.15.0 native check, October 10, 2026

Three installed clients completed the native exchange on Linux against the exact x86-64 wheel and source archive from [publish run 38086567022](https://github.com/jointsome0-lgtm/harness-talk/actions/runs/38086567022), source commit `45603ee2c2c47afb53b97211a39af073716ef036`: Codex and Claude Code as real sessions in both initiating directions, and OpenCode as a real server with a deterministic local provider. This is the scope the repository owner set for 0.13.0, kept for 0.14.0 and for this release. The other eleven installed clients were not checked live for this release; their last live check is the [0.12.0 native check](2026-10-05-0.12.0-native.md).

No client ran on macOS or Windows. What is new in 0.15.0 is on macOS: notices into Codex and Claude Code, their discovery, `receive` and the recognition of a session. This check does not touch any of it. What stands behind it is the publish run on GitHub's hosted runners, against the fake clients of the test suite, described below. No real Codex or Claude Code has run on a Mac, and no notice has reached a real session there. [What works on which system](../platforms.md) says what backs each part.

## Codex and Claude Code

| Installed client | Observed version | Model and permissions |

| Codex CLI | 0.160.0 | GPT-6.1 Sol, low effort; sandbox `workspace-write`, approval `on-request`; each of its seven htalk commands asked to run outside the sandbox |
| Claude Code | 2.1.296 | Sonnet 5.5; the account's default `auto` permission mode, with one rule allowing the wheel's executable |

Each client ran as an ordinary interactive session in its own empty workspace, with the account's normal client configuration, in a terminal multiplexer started with a clean environment. The mailbox was new and the text invented. These were actual model calls. Token counts and billing were not measured, and the model names are the ones the clients displayed. Codex offered an update to 0.161.0 at start; it was declined.

Each recipient compared the shown id with the id in its notice and checked sender, recipient, body and `in_reply_to` before the ack. All four rows are acknowledged and both final inboxes are empty. Each session's own transcript holds exactly its two notices. No result in either transcript carries `notification_started_at`, which an executable older than 0.13.0 would print. Both sessions printed `0.15.0` for `--version` before the exchange, and every htalk command in both transcripts names the wheel's executable by its absolute path. The mailbox is on schema 3. The exchange ran from 21:24:32 to 21:27:46 UTC.

Ack cleanup was literally `unsupported` with `client_has_no_notification_removal` for Claude and `absent` with the queue id for Codex. Neither proves that a notice was removed. Both clients ended with exit status 0 after their own quit command.

## OpenCode

OpenCode 1.18.32 ran as `opencode serve` on a loopback port with new state directories and a fake key. The model was a local script that speaks the chat-completions protocol on loopback, so no model call was made and the result says nothing about model comprehension. Only the htalk MCP tool, bound to the wheel's executable, was offered to it.

`peer check` reported the session as `idle` on a server of version 1.18.32. A pull peer acting as controller sent one question. htalk answered `submitted` with `opencode_prompt_async_accepted` and returned the answer inside its 45-second wait. The session's own history holds the notice once and three tool calls: show, ack, reply. The local provider checked id, sender, recipient, body and `in_reply_to` of the shown message before it asked for the ack. The controller showed the answer, checked that it answers the question, and acknowledged it separately. Both final inboxes are empty. The provider served five requests, one for the session title and four for the exchange.

Ack cleanup was literally `unsupported` with `client_has_no_notification_removal` in the session and `skipped` with `pull_only` at the controller; neither proves that a notice was removed. The server ended with -15 after SIGTERM, which is not a normal exit of its own. A request for port 0 selected 4096, so an OS-assigned port was not shown. No attached TUI was checked.

## Scope and limits

- Linux x86-64 only. No Codex, Claude Code or OpenCode ran on macOS or Windows, and no wheel but the Linux x86-64 one was executed outside the publish run.
- The macOS port of native delivery, which is what this release adds, was not exercised by any real client. A notice to a real session on a Mac is still to be seen.
- A Claude Code session started with `CLAUDE_CONFIG_DIR`, which this release finds, was not part of this check.
- Not checked live for 0.15.0: Pi, Oh My Pi, OpenClaw, Cline, Kilo, Goose, Hermes, GitHub Copilot CLI, Gemini CLI, Letta Code and OpenHands. Here their adapters are covered only by the adapter tests of the publish run. Antigravity SDK and Agent Zero remain unchecked, as before.
- The notice names `htalk`. Both core sessions ran the wheel's absolute path in its place, because an older htalk is installed on the same machine. A notice followed word for word on a machine whose first `htalk` is 0.15.0 was not observed.
- One exchange in each direction. No interruption, recovery, concurrent writer or route between devices was exercised. The wait of a queued send, which this release times by the clock, was not exercised live; the tests of the publish run cover it.
- Native exit was observed as an exit status. What htalk owns while it delivers, process groups, pidfds and listeners, was not observed closing in this check; the tests of the publish run cover it.
- The clients used the account's normal configuration and network. Nothing is claimed about the processes or the traffic of the whole host.
- The installed clients and the older installed htalk were not changed.
